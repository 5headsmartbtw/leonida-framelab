# Как участвовать в Leonida FrameLab

[English](CONTRIBUTING.md) · [Координация и задачи](https://github.com/5headsmartbtw/leonida-framelab/issues/4) · [План разработки](docs/ROADMAP.md)

## Файлы GTA VI запрещены

**Любые файлы GTA VI строго запрещены в PR и в каждом его коммите.** Запрет распространяется на материалы игры, включая ранние сборки и утечки: исполняемые файлы, архивы, исходный код, ключи, ресурсы, шейдеры, захваты, дампы и извлечённые данные. Переименование, упаковка, кодирование или частичное удаление данных запрет не снимают. Он также действует для тестовых данных, логов с данными игры, скриншотов, артефактов, Git LFS, ссылок и вложений в PR и Issues, через которые распространяются такие материалы. Если происхождение файла нельзя подтвердить, замените его синтетическим примером.

Используйте самостоятельно созданные сцены, синтетические данные и технические логи без чувствительных сведений. Для стороннего кода укажите источник, ревизию и лицензию, разрешающую распространение. Проприетарные заголовки, бинарники и ядра NVIDIA в PR не принимаются. Сохраняйте уведомления Apache-2.0 и MIT для заимствованного кода. Новый оригинальный код публикуется под MIT.

## Как взять задачу

1. Проверьте координационный issue, существующие задачи и открытые PR. Используйте номер issue или ID из таблицы задач. Для существенной работы напишите `/claim #1` или `/claim FL-01`, укажите границы изменений, зависимости и план проверки. Дождитесь подтверждения сопровождающего. Мелкие исправления и сообщения о проблемах можно предложить без заявки.
2. Пишите `/progress #1`, чтобы сообщить о результатах или препятствии, `/unclaim #1`, чтобы освободить задачу, и `/propose`, чтобы предложить новую. Команды разбираются вручную.
3. Откройте PR по одной задаче и свяжите его с issue. Укажите изменение, проверенный коммит, команды, фактические результаты, пропущенные проверки, происхождение материалов и существенное участие ИИ, если оно было.

## Проверки перед слиянием

```sh
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
python scripts/check_repository.py
python scripts/check_no_game_files.py --base origin/main
```

Последнюю команду запускайте после коммита в своей ветке. Она проверяет историю PR. CI ищет известные признаки запрещённых файлов и запускает переносимые тесты на Windows и Linux. Происхождение исходников и материалов проверяется вручную при ревью.

Для изменений рендеринга приложите применимые результаты на синтетической сцене. Укажите GPU, драйвер, ОС, SDK/runtime, API и команды воспроизведения. Различайте отрисованные кадры, сгенерированные изображения, вызовы Present и реальные измерения вывода на монитор. Не подставляйте вымышленные depth, motion vectors или данные камеры. Сохраняйте фактические результаты проверки возможностей. Требования к проверкам на GPU описаны в [инструкциях по сборке](docs/BUILD.md).
