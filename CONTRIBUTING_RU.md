# Как участвовать в Leonida FrameLab

[English](CONTRIBUTING.md) · [Координация и задачи](https://github.com/5headsmartbtw/leonida-framelab/issues/4) · [План разработки](docs/ROADMAP.md)

## Файлы GTA VI запрещены

**Любые файлы GTA VI строго запрещены в PR и в каждом его коммите.** Запрет распространяется на материалы игры, включая ранние сборки и утечки: исполняемые файлы, архивы, исходный код, ключи, ресурсы, шейдеры, захваты, дампы и извлечённые данные. Переименование, упаковка, кодирование или частичное удаление данных запрет не снимают. Он также действует для тестовых данных, логов с данными игры, скриншотов, артефактов, Git LFS, ссылок и вложений в PR и Issues, через которые распространяются такие материалы. Если происхождение файла нельзя подтвердить, замените его синтетическим примером.

Используйте самостоятельно созданные сцены, синтетические данные и технические логи без чувствительных сведений. Для стороннего кода укажите источник, ревизию и лицензию, разрешающую распространение. Проприетарные заголовки, бинарники и ядра NVIDIA в PR не принимаются. Сохраняйте уведомления Apache-2.0 и MIT для заимствованного кода. Новый оригинальный код публикуется под MIT.

## Как взять задачу

1. Проверьте [Coordination #4](https://github.com/5headsmartbtw/leonida-framelab/issues/4), существующие задачи и открытые PR. Для существенной работы напишите в #4 `/claim FL-01` или `/claim #3`. Укажите одну команду в первой строке, а объём изменений, зависимости и план проверки опишите ниже. Мелкие исправления и сообщения о проблемах можно предложить без заявки.
2. Бот сразу резервирует любую доступную задачу, включая реализацию SDK и архитектурные изменения. Можно начинать работу, как только бот подтвердит заявку и пришлёт описание задачи и критерии приёмки. Для всех PR по-прежнему действуют обычные правила ревью, CI и защиты веток.
3. Напишите в #4 `/progress FL-01`, чтобы отметить свою задачу как находящуюся в работе и добавить в таблицу ссылку на обновление. Напишите о результатах или препятствиях ниже команды. Используйте `/unclaim FL-01`, чтобы освободить свою задачу. Чтобы предложить новую задачу, используйте `/propose`.
4. Откройте PR по одной задаче и свяжите его с issue. Укажите изменение, проверенный коммит, команды, фактические результаты, пропущенные проверки, происхождение материалов и существенное участие ИИ, если оно было.

Для каждой команды создавайте новый комментарий. Сопровождающие добавляют новые задачи в разделы **Work available** или **New tasks** в #4 и помечают их как `Available`. Перед ручным обновлением статусов дождитесь выполнения команд в очереди. При редактировании других полей строки сохраняйте маркер `framelab-claim`.

## Проверки перед слиянием

```sh
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
python scripts/check_repository.py
python scripts/check_no_game_files.py --base origin/main
```

Последнюю команду запускайте после коммита в своей ветке. Она проверяет историю PR. CI ищет известные признаки запрещённых файлов и запускает переносимые тесты на Windows и Linux. Происхождение исходников и материалов проверяется вручную при ревью.

Для изменений рендеринга приложите применимые результаты на синтетической сцене. Укажите GPU, драйвер, ОС, SDK/runtime, API и команды воспроизведения. Различайте отрисованные кадры, сгенерированные изображения, вызовы Present и реальные измерения вывода на монитор. Не подставляйте вымышленные depth, motion vectors или данные камеры. Сохраняйте фактические результаты проверки возможностей. Требования к проверкам на GPU описаны в [инструкциях по сборке](docs/BUILD.md).

## Изменения GPU и проверка при ограниченной видеопамяти

Сохраняйте ранее проверенные сочетания оборудования и runtime, а также совместимость установленного публичного ABI. Проверяйте возможности GPU и runtime перед включением необязательных функций. Если функция недоступна или выделить память не удалось, сохраняйте возможность обычного рендеринга. Указывайте официальную поддержку NVIDIA отдельно от экспериментальных профилей совместимости. Для применимых сценариев добавляйте воспроизводимые проверки синхронизации и времени жизни ресурсов с включённым слоем отладки D3D12 или проверкой синхронизации Vulkan.

Проводите проверки на доступном вам оборудовании. В PR укажите команды, конфигурации, фактические результаты и явные пропуски. Перед слиянием применимых изменений сопровождающий сравнивает последнюю рабочую версию и предлагаемую ревизию на RTX 2050 Laptop GPU (4 ГБ) при 1280×720. Нагрузочные тесты и замеры на RTX 5090 дополняют эту проверку. Метрики, допуски по результатам повторных базовых замеров и сценарии проверок описаны в [чек-листе релиза SDK](docs/sdk/RELEASE_CHECKLIST.md#rtx-2050-low-memory-merge-gate).
